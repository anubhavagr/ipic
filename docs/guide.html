Architecture & User Guide

◆ ipic

A lightweight, blazingly fast multimodal file manager with fully on-device RAG search. Type or speak a natural-language query and ipic finds it across your text files, PDFs, audio, video and images — no cloud, no API calls, no telemetry.

Rust · egui 100% offline after first model fetch ~318 MB total disk footprint single-digit ms search latency all cores during indexing

01Overview

ipic is a native desktop application that combines two things that usually live in separate products: a proper file manager (tree navigation, sorting, filtering, bulk operations) and a local multimodal search engine (semantic + keyword + acoustic retrieval over your file contents).

Everything executes on your machine. The two neural models (a text embedder and a speech-to-text encoder) are cached locally after a one-time download; from then on the app works fully offline. No query, filename, transcript or embedding ever leaves the process.

03Quickstart

Requirements

  • Rust 1.94+ and cmake (whisper.cpp builds automatically)
  • macOS on Apple Silicon is the primary target; Linux works with the same code paths
  • ffmpeg optional — broadens A/V container coverage; wav/mp3/flac/ogg/m4a decode fine without it
  • ~250 MB free disk for the two local models (downloaded once, then fully offline)

Build & run

$ git clone https://github.com/anubhavagr/ipic && cd ipic
$ cargo build --release

# GUI
$ ./target/release/ipic

# or headless
$ ./target/release/ipic-cli scan                       # index everything under roots (live progress bar)
$ ./target/release/ipic-cli search "radiation shielding on mars"
$ ./target/release/ipic-cli ask --audio question.wav   # spoken/audio query
$ ./target/release/ipic-cli status                     # index statistics
$ ./target/release/ipic-cli list --kind video
$ ./target/release/ipic-cli config --set-roots ~/Downloads ~/Movies

Default scope is ~/Downloads. First run downloads bge-small-en-v1.5 (~130 MB) and whisper small.en q5 (~180 MB) into ~/.ipic/models/.

04Architecture

Four crates in one Cargo workspace, layered strictly downward. The GUI is a thin shell over the engine — every screen reads through catalog connections and engine events, never the filesystem directly, which is what makes the UI swappable (a TUI or web front-end could drive the same engine).

05The four crates

CrateResponsibilityKey pieces
ipic-core Filesystem truth: scanning, cataloging, watching. Directory-queue parallel walker (all cores, symlink-safe, skip-list); SQLite catalog in WAL mode with batched upserts; FTS5 full-text index; notify-based debounced watcher that triggers incremental rescans; TOML config scoped to the engine's data directory.
ipic-rag Understanding: embeddings, ASR, fingerprints, retrieval, orchestration. Neural embedder (bge-small-en-v1.5 via ONNX Runtime) with a deterministic feature-hashing fallback for offline first-runs; whisper.cpp transcriber (Metal-capable, CPU/Accelerate default) sharing one context across a state pool; pure-Rust acoustic fingerprinting (rustfft); two mmap'd i8-quantized vector stores; hybrid search with weighted reciprocal-rank fusion; the Engine — worker threads, event bus, crash-safe Pending/Busy/Done/Failed job states.
ipic-app The GUI. egui/eframe with a light minimal theme, embedded Inter + JetBrains Mono + Material Icons; virtualized table with multi-select; unified search bar with mic capture (cpal); floating inspector; settings. Ships as a library + thin binary so tests drive the real app.
ipic-cli Headless driver. scan (live progress bar, resumable), search, ask --audio, status, list, config.

06Indexing pipeline

Background, resumable, and crash-safe. A file's lifecycle in the catalog is an explicit state machine — Pending → Busy → Done / Failed — persisted in SQLite so an interrupted run resumes cleanly on next launch (Busy rows reset to Pending at open).

  1. Scan — a shared directory queue feeds one worker per CPU core; discovered entries stream over a channel to a single-writer collector that batches upserts into SQLite (8k rows/tx). Each directory is registered on arrival so child files always resolve their parent.
  2. Claim — extraction workers self-serve jobs from the catalog with an atomic UPDATE … RETURNING claim (natural backpressure). Two lanes: a fast lane for text/PDF/images, a slow lane for audio/video gated by a semaphore sized to the whisper state pool.
  3. Extract — text files are read (UTF-8 validated, size-capped); PDFs go through a panic-guarded extractor (malformed PDFs are contained, marked Failed); images produce a filename + folder-context pseudo-document; audio/video are decoded to 16 kHz mono PCM (ffmpeg pipe when available, else pure-Rust symphonia).
  4. Transcribe (media lane) — whisper with beam-search decoding; duration is recorded; a 128-dim acoustic fingerprint is computed from the same PCM and stored in the fingerprint vector store.
  5. Chunk — ~320-word windows with a 24-word overlap so boundary context stays searchable.
  6. Embed — a dedicated writer thread batches up to 64 chunks through the ONNX embedder (intra-op pool sized to leave headroom for the other pools) and persists FTS5 rows + quantized vectors transactionally, then flips files to Done.

A notify-based watcher follows the scan: created/modified files are re-upserted (changed size or mtime resets the file to Pending), deletions purge rows and free both vector-slot spaces, and changed subtrees get incremental rescans.

07Storage formats

Everything lives under ~/.ipic/. Nothing is opaque — each artifact is a standard format you can inspect.

ArtifactFormatContents

Why i8 quantization

Vectors are stored one byte per component — 4× smaller than f32 — and scanned as pure integer dot products that the compiler auto-vectorizes with NEON. The mmap means the resident cost of the index is near zero: the OS page cache serves scans, and only hot pages stay in RAM. Ranking accuracy loss versus f32 is negligible for retrieval.

08Search internals

One query, four retrieval lanes, fused by weighted reciprocal-rank fusion:

  • Query path: embed query → parallel integer top-k over the mmap'd store (4096-record shards, partial top-k per shard, merge) → hydrate chunk rows → aggregate per file.
  • Safety: FTS5 MATCH expressions are built from quoted words only — no operator injection; LIKE patterns escape wildcards.
  • Spoken queries add the acoustic lane and display the interpreted transcript (“🎙 heard: …”).

09Audio-to-audio matching

Text embeddings can't hum. For direct sound-to-sound similarity, every audio/video file gets a 128-dimensional acoustic fingerprint at index time, computed from the same decoded PCM the transcriber sees:

  1. Hann-windowed 1024-sample frames, 512 hop → FFT (rustfft, pure Rust).
  2. Power spectrum folded into 64 log-spaced bands (80 Hz – 7.6 kHz), log-compressed.
  3. Two statistic halves per band — spectral shape (mean log-energy) and spectral flux (frame-to-frame change RMS) — each unit-normalized separately so timbre and dynamics weigh equally.

Similarity is the cosine between query and indexed fingerprints: the same recording re-encoded, trimmed, or re-mastered matches strongly; the metric degrades gracefully toward “sounds alike”. Tests pin self-similarity ≈ 2.0 (two unit halves) and separate spectrally distinct material well below 0.8× self.

11The GUI

Native egui, single process, GPU-rendered, ~60 MB resident. Light minimal theme: near-white canvas, hairline borders, one electric-blue accent, Inter typography, Material Icons throughout.

  • Top bar — back / forward / up, clickable breadcrumbs, and the unified search box with mic button and ⌘F focus.
  • Sidebar — locations (roots), kind filters with live counts, and a lazy-expanding directory tree.
  • Toolbar — new folder, rescan, kind chips, Large (>100 MB) / Recent (30 days) toggles, sort key + direction.
  • Table — virtualized for huge folders; status dot before each icon; multi-select with ⌘/⇧/⌘A; double-click opens; right-click menu performs bulk open / reveal / copy paths / duplicate / trash.
  • Floating inspector — appears only while a row is selected: metadata, indexed-content preview, image preview, quick actions. Deliberately a floating window: an appearing side panel re-flows the table and used to close open context menus.
  • Footer — index health (files, vectors, cores) on the left; progress cluster (fraction bar + spinner) on the right.

13Configuration

~/.ipic/config.toml — editable by hand or via ipic-cli config / the settings window. Root changes take effect on the next rescan without a restart.

roots            = ["/Users/you/Downloads"]   # indexed scopes
skip_dir_names   = [".Trash", "Library", "node_modules", …]
whisper_model    = "small.en-q5_1"   # tiny/base/small × .en/multilingual, q5_1
whisper_workers  = 3                    # concurrent decode states (CPU path)
whisper_use_gpu  = false                # Metal: fastest, serializes on one state
embedder         = "neural"             # or "hashing" — offline lexical fallback
embed_batch      = 64                   # chunks per ONNX batch
max_text_mb      = 8                    # per-file extraction cap

15Testing strategy

59 tests across the workspace, including 50 UI tests that drive the real application with synthetic mouse and keyboard input via egui_kittest — clicks are emitted with real-input semantics (press and release in separate frames, 1 ms simulated clock so double-click windows hold).

  • Unit — chunker bounds, resampler, FTS5 quoting, vector-store round-trip (append → top-k self-match → free/reuse), fingerprint self-similarity and separation.
  • Integration — full scan → catalog → embed → hybrid-search flow on a synthetic corpus with the deterministic hashing embedder (hermetic: temp data directories, no model downloads).
  • UI suites — search (Enter/Esc/filtering/no-results), navigation (breadcrumbs, history, tree, library structure), file operations (rename/duplicate/trash/new-folder against a real temp filesystem), toolbar (sorting, filters, settings, rescan), interaction (select, double-click open, right-click menu, Enter open).
  • Seams — open/reveal actions are injectable, so tests assert routing without spawning Finder; engines launched against temp directories never touch your real config or index (verified byte-identical after full suite runs).

16Privacy model

Nothing leaves this machine. Ever.

  • Both models run locally (ONNX Runtime / whisper.cpp) and are cached after one download.
  • No analytics, no telemetry, no network code beyond the initial model fetch (and the optional update path you trigger yourself).
  • All derived data — transcripts, embeddings, fingerprints — lives in ~/.ipic/ as inspectable SQLite and flat files. Delete the directory and every trace is gone.

17Limits & roadmap

  • Speech-centric audio. Non-speech sound (music, ambience) matches acoustically and by metadata, but has no semantic representation yet — a CLAP-style encoder is the natural extension, and the per-modality store design slots it in without pipeline changes.
  • Image search is name+context based. Content-based image retrieval (CLIP) would follow the same two-store pattern.
  • Flat vector index. Exact integer scan is optimal to a few million vectors (~30 ms at 2 M × 384-dim on one core, faster across cores); HNSW becomes worthwhile beyond that.
  • Rename/move propagation relies on the watcher's incremental rescan — instant in practice, eventually-consistent by design.
  • Future: edge-AI targets (the core crates are dependency-light by design), mobile companions sharing the catalog format, per-modality model swaps via config.
